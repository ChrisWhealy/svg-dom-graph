Booleans and pointer-sized integers

A data node can hold bool values, and usize and isize, the integers that are as wide as a pointer. Each is a type of its own, with its own colour and its own name for assistive technology.

Booleans

A BoolFormat chooses how true and false are written: as the words, as the bits 1 and 0, or as a green check mark and a red cross. The marks have different shapes, so colour is not the only thing that tells them apart, and a screen reader is told true or false and never the name of a glyph. Every format gives both values a cell of the same width, so a node that changes from one to the other does not outgrow its cells. Under any other format a Boolean is the single byte it is held in.

Logical operators

A Boolean can be an operand of NOT, AND, OR, XOR, NAND, NOR and XNOR, as the truth table below shows, whichever way each is written: each row of the table uses a different format. It cannot be an operand of a shift, a rotation, a reversal or an arithmetic operator, since there is no sum of two Booleans and no true to rotate. Use a u8 for a one-bit number.

Pointer-sized integers

The width of a usize or an isize is that of the compilation target. This demo runs on wasm32, where it is 32 bits, so the largest usize value is 4294967295 and its hexadecimal representation occupies four bytes.

On a 64-bit host it would have twenty decimal digits and occupy eight bytes. A wasm64-unknown-unknown target exists, but it has no precompiled standard library, so building for it would require the use of a nightly compiler. This crate is built and tested for wasm32 only, so wasm64 is not a supported build target.
