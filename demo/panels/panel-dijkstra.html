Dijkstra's Shortest Paths

Dijkstra's algorithm finds the shortest route from one vertex of a weighted graph to another.

The algorithm works by repeatedly applying two steps:

  1. Update cost estimates of visiting neighbouring vertices
  2. Choose which vertex to visit next

For each vertex, a list is kept that holds two values:

  • The path length (or weight or cost) found so far to that vertex
  • The vertex we started from to get there

Notice that we use the idea of a cost estimate. Until all the vertices in the graph have been traversed, we cannot yet be certain that shortest path has been found, so each traversal cost is treated as a temporary value that might, in future, be reduced.

Before we start traversing the graph, we have no idea what the cost will be of getting from one vertex to another, so all the costs starts at infinity. At the start however, all we can say for certain is that if we start at vertex A, then the cost of getting to vertex A is zero — because we're already there!

It should also be pointed out that this implementation of Dijkstra's algorithm only works for edge weights greater than zero.

Update cost estimates of visiting neighbouring vertices

Once we have determined the cost of reaching a particular vertex, we will label that vertex as visited or explored or, as we say in this demo settled. We look at the current cost estimate we held for visiting that node, and if we find we have traversed a cheapr path, then we can reduce our cost estimate. This means that on the first visit to a vertex, the actual cost will always be smaller than infinity, so that value is replaced with the cost found so far.

The cost estimate of visiting a vertex is the sum of the edge costs currently traversed before arriving at that vertex. What we can be certain of is that the cost estimate of visiting a vertex may go down, but it will never go up.

Choose which vertex to visit next

The rule for choosing which vertex to visit next is simply to follow the edge with the lowest cost or weight. Now that we have visited this vertex, we first mark it as settled and we then repeat the two steps listed above.
