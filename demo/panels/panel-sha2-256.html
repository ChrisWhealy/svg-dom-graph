SHA2-256

SHA-256 hashes a message in 64-byte blocks. This demo hashes one short message, so it needs only one block. Every value on screen is a real result of that one calculation, worked out in plain Rust.

The message block

The message is padded out to one 64-byte block, seen as 16 big-endian 32-bit words. The byte straight after the last message byte is the terminator, 0x80. The last 64 bits hold the message's length in bits, big-endian. This message is short, so only the last word, w15, is used.

The message schedule

The block is copied into the first 16 words of a 64-word schedule. Each of the other 48 is the sum of four earlier words, ignoring overflow: ms[n-16] + sigma0(ms[n-15]) + ms[n-7] + sigma1(ms[n-2]). While a word is being built, it is marked, and the four words it reads are marked as secondary.

sigma0(w) is ROTR(w, 7) XOR ROTR(w, 18) XOR SHR(w, 3), and sigma1(w) is ROTR(w, 17) XOR ROTR(w, 19) XOR SHR(w, 10).

Compression

Eight working variables, a to h, start as the initial hash value: the first 32 bits of the fractional parts of the square roots of the first 8 primes. The 64 round constants K are the same for the cube roots of the first 64 primes. Each round uses one schedule word and one constant.

temp1 = h + bigSigma1(e) + choice(e, f, g) + K[i] + W[i] and temp2 = bigSigma0(a) + majority(a, b, c), where bigSigma0(w) is ROTR(w, 2) XOR ROTR(w, 13) XOR ROTR(w, 22), bigSigma1(w) is ROTR(w, 6) XOR ROTR(w, 11) XOR ROTR(w, 25), choice(e, f, g) is (e AND f) XOR (NOT(e) AND g), and majority(a, b, c) is (a AND b) XOR (a AND c) XOR (b AND c).

The next working variables are h=g, g=f, f=e, e=d+temp1, d=c, c=b, b=a, a=temp1+temp2.

The digest

After 64 rounds, each working variable is added to the initial hash word it started as. The digest is those 8 words, joined. Without that last addition, the result would not be a hash of the block.
