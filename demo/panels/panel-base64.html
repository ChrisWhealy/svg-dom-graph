Base64 Encoding

Base64 encodes a a sequence of bytes using only of printable characters, so they can transmitted as "plain text" as opposed to raw binary. This means that BAse64 data can be included in the body of an email or sent as a query string value in a URL.

It operates by taking three byte of the input (which equalts 24 bits), then dividing those 24 into four, 6-bit slices. A six bit number is than some value in the range 0 to 63.

We now need to map that 6-bit number to a printable character. There are:

  • 26 uppercase letters (values 0..25)
  • 26 lowercase letters (values 26..51)
  • Ten digits (values 52..61)
  • 62 is encoded as a +
  • 63 is encoded as a /

These characters make up what is known as the Base64 alphabet . When used in a URL, the Base64URL alphabet is used in which a - is used for 62, and _ is used for 63. This is to prevent the + and / characters from being misinterpreted by the HTTP protocol.

If the input does not divide into whole groups of three bytes, the last group is padded with zero bits. One byte leaves two characters to fill and two bytes leave one. These are written as =, so the output is always a multiple of four characters long.

Type in the text input node. Its bytes appear in the hex dump, then below it as six-bit values, then back up the page as a second hex dump of the characters they stand for. The six-bit values are laid out four groups to a row, and the node has a row only when the text needs one. The first hex dump has room for 256 bytes, so any text past that is not encoded, and it dims the bytes that the text does not reach. The six-bit values behind a padding character are dimmed too.
