Base64 Encoding

Base64 encodes a sequence of bytes using only printable characters. The purpose being to allow the encoded text to be transmitted as "plain text" rather than raw binary. This means that Base64 data can be included say, in the body of an email or supplied as a query string value in a URL.

It operates by taking three bytes of the input (which equates to 24 bits), then dividing those 24 bits into four, 6-bit slices. A 6-bit number is is always a value in the range 0 to 63.

The 6-bit values are then mapped to one of 64 printable characters taken from the alphabetic and numeric characters in standard 7-bit ASCII. There are:

  • 26 uppercase letters (the 6-bit codes 0..25 map to characters A..Z)
  • 26 lowercase letters (the 6-bit codes 26..51 map to characters a..z)
  • Ten digits (the 6-bit codes 52..61 map to digits 0..9)
  • 62 is encoded as a +, and
  • 63 is encoded as a /

These characters make up what is known as the Base64 alphabet . When used in a URL, the Base64URL alphabet is used in which a - is used for 62, and _ is used for 63. This is to make the + and / characters HTTP-safe.

If the input does not divide into whole groups of three bytes, the last group is padded with zero bits. One byte leaves two characters to fill and two bytes leave one. These are written as =, so the output is always a multiple of four characters long.

Type in the text input node. Its bytes appear in the hex dump, then below it as six-bit values, then back up the page as a second hex dump of the characters they stand for. The six-bit values are laid out four groups to a row, and the node has a row only when the text needs one. The first hex dump has room for 256 bytes, so any text past that is not encoded (the cut falls between characters, never inside one), and it dims the bytes that the text does not reach. A note beside the text input node gives the length of the text, and says how much is left out when it is too long. The six-bit values behind a padding character are dimmed too. Each change draws the diagram again, so a node that has been dragged returns to its place. Zoom and pan are kept.
