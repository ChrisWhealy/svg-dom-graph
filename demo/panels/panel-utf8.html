UTF-8 Encoding

Unicode gives every character a number, called its code point and written U+0041 for A. UTF-8 is the way those numbers are turned into bytes. It uses one byte for the 128 ASCII characters, so ASCII text is already valid UTF-8, and two, three or four bytes for everything else. Most text on the web is UTF-8.

The number of bytes depends on the size of the code point:

Code points Bytes Template Bits of the code point
U+0000 to U+007F 1 0xxxxxxx 7
U+0080 to U+07FF 2 110xxxxx 10xxxxxx 11
U+0800 to U+FFFF 3 1110xxxx 10xxxxxx 10xxxxxx 16
U+10000 to U+10FFFF 4 11110xxx 10xxxxxx 10xxxxxx 10xxxxxx 21

The range of three bytes leaves out values in the U+D800 to U+DFFF. Those are the surrogates, which UTF-16 uses in pairs to write the characters above U+FFFF. They are not characters in their own right, and UTF-8 forbids encoding them.

The bits of the code point fill the xs from the left. The bits that are not x are the template, and they make the encoding self-describing. The first byte starts with as many 1s as there are bytes in the sequence, followed by a 0. Every byte after the first starts with 10, so a reader that starts in the middle of a text can always find where the next character begins.

Choose one of the four characters along the top, one for each length of sequence: A takes one byte, £ two, € three, and an emoji four. Under them is the code point, then the bits of the code point, then the bits of the encoded bytes with the template highlighted, and last the bytes in hexadecimal.
