Text nodes

Two nodes hold text rather than values. A Markdown node explains something in prose, next to the thing it explains. A text input node holds a text box the user types into.

The Markdown node

It draws headings, paragraphs, bulleted and numbered lists, and bold, italic and code runs. Its width is chosen by the caller, and its height is whatever the text needs. Text that is too long for a line wraps between words. This crate has no Markdown dependency. The node's text is drawn as SVG that the crate lays out itself, in a monospace font, so a general parser that produces HTML would give it nothing it could use. See the docs for the subset it understands.

The text input node

The text box is an ordinary HTML <input> inside the node. So the caret, selection, the clipboard and input methods are the browser's own, and the box is named for assistive technology by the node's label. Typing in it never pans or zooms the diagram.

A callback is given the text each time it changes. Here it writes the text to the line below the diagram.

Both nodes can be dragged, like any other node, and the connector follows.
