SHA3 Sponge

The SHA3 algorithm belongs to a category of functions known as "sponge" functions. This means that they process their input data in two distinct, strictly sequential phases: absorption and squeezing.

Absorption

The input data is ingested or "absorbed" into the algorithm's internal state.

The absorption process reads the input data one block at a time into a subdivision of the internal state known as the "Rate". This subdivision is so-named because its size directly effects the rate at which the incoming data can be processed.

Each time an input block is acquired, that data is XORed with the data currently in the Rate, then the Keccak-f[1600] function is applied to the entire internal state.

The remaining part of the internal state is known as the "Capacity" and this is always kept private.

This is where the input data is mixed in such a way to make the resulting output cryptographically strong.

Squeezing

Once the input data has been fully absorbed into the internal state, the output or "Squeeze" phase can begin.

In the simplest case (demonstrated here), whatever data is found in the first 256 bits of the Rate immediately equates to the SHA3-256 hash of the input data. When used in this manner, the SHA3 function can be described as a "drop-in" replacement for the SHA2-256 algorithm.

However, even though all the input data has been consumed, the Keccak-f[1600] function can be repeatedly applied to the internal state to create an entirely deterministic stream of psuedo-random content.

For the same input, running multiple "squeeze" rounds (I.E. repeatedly running the Keccak-f[1600] function on the internal state) will always produce exactly the same output.
