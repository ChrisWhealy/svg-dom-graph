SHA3 Sponge

SHA3 is built on the "sponge" construction. A fixed-size internal state, split into a "Capacity" and a "Rate", absorbs input data a block at a time, each block XORed into the Rate before the whole state is permuted by Keccak-f[1600]. This is a drop-in replacement for the SHA2 family, built on a different, provably secure foundation rather than SHA2's own Merkle–Damgård design.

This first diagram shows a single 64-byte input block passing through one call to Keccak-f[1600]. "Keccak f(1600)" is drawn as a plain box for now, not yet a container node. Drilling into a real nested Scene for the permutation itself is a later step, and so are processing more than one input block and SHA3's Extendible Output Function (XOF) mode.

Row 1's own "Capacity" and "Rate" start all-zero, the sponge's own real state before any input is absorbed. "Input block" holds one real 64-byte input, not a placeholder. "Keccak f(1600)" does not yet compute anything, so row 3's own "Capacity"/"Rate" are still fixed placeholders, not real outputs of row 1's own values. "XOR" is the one real computation this diagram performs, once it runs: its own content is the true elementwise XOR of "Rate" and "Input block", computed in plain Rust.
