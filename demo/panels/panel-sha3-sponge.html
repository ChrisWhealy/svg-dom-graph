SHA3 Sponge

SHA3 is built on the "sponge" construction. A fixed-size internal state, split into a "Capacity" and a "Rate", absorbs input data a block at a time, each block XORed into the Rate before the whole state is permuted by Keccak-f[1600]. This is a drop-in replacement for the SHA2 family, built on a different, provably secure foundation rather than SHA2's own Merkle–Damgård design.

This first diagram shows a single 64-byte input block passing through one call to Keccak-f[1600]. "Keccak f(1600)" is a genuine container node: click it to drill into all 24 real rounds of the permutation. Processing more than one input block and SHA3's Extendible Output Function (XOF) mode are still out of scope.

Each round shows five named sub-functions — Theta, Rho, Pi, Chi, Iota — and the real round constant Iota would consume, highlighted in "Round Constants". Theta is itself a genuine nested Scene — the same one Nested Scenes already draws standalone — so it drills in one level further.

Rho, Pi, Chi, and Iota are plain placeholder boxes. Each round's own output array is a clearly fake placeholder too, not a real permutation of its input. Implementing SHA3's real rotate-by-offset, lane-permute, non-linear-combine, and constant-XOR steps is a larger feature than this diagram covers.

Row 1's own "Capacity" and "Rate" start all-zero, the sponge's own real state before any input is absorbed. "Input block" holds one real 64-byte input, not a placeholder. Row 3's own "Capacity"/"Rate" at this top level are still fixed placeholders, not real outputs of row 1's own values or of what happens inside "Keccak f(1600)". "XOR" is the one real computation this diagram performs, once it runs: its own content is the true elementwise XOR of "Rate" and "Input block", computed in plain Rust.

Press "Next"/"Previous"/"Restart" below the diagram to walk the five stages of one Keccak-f[1600] call, moving a focus ring from "Input block"/"Rate", to "XOR", to "Keccak f(1600)", to the output "Capacity"/"Rate", and finally to "Output Hash". "XOR" shows all-zero lanes, the same "not yet written" look row 3 already uses, until the walk actually reaches it — only then does it show its own real result.
